# AI 视频识别信号平台用户手册

编写日期：2026-05-14（最后更新：2026-06-02）  
版本：v0.3.0  
项目目录：`D:\Project`  
适用对象：演示人员、组员、测试人员、管理员、后续接手开发人员。

## 1. 系统说明

本系统用于园区、仓库、码头等场景的视频安全监测。系统通过摄像头或上传视频获取画面，使用 YOLO 进行人员检测，通过规则引擎判断人员翻越围栏、人员滞留等事件，并生成告警、回放、视频理解和 Agent 处置建议。

当前保留的核心业务场景：

1. 园区内部围栏检测：翻越围栏检测、围栏区域人员滞留检测。
2. 仓库+码头滞留检测：码头区域人员滞留、仓库区域人员滞留。

系统核心能力：

- 实时监控矩阵。
- 告警事件大屏。
- 具体摄像头监控页。
- 上传视频识别。
- 同一局域网手机实时摄像头接入。
- 翻越和滞留规则告警。
- 事件回放和短片段裁剪。
- 回放视频检测框叠加。
- MiMo 视频理解。
- Agent 告警查询和回放定位。
- 管理员登录。
- 区域绘制和滞留阈值调整。
- 截图和录屏。
- YOLO / VLM 单摄像头双引擎切换。
- 项目打包和组员电脑复现。

```powershell
.\setup_env.bat
.\start_all_dev.bat
```

### 2.2 日常启动

如果环境已经安装好，只需要：

```powershell
Set-Location D:\Project
.\start_all_dev.bat
```

### 2.3 打开系统

首页：

```text
http://127.0.0.1:5500/index.html
```

后端健康检查：

```text
http://127.0.0.1:8000/health
```

正常返回示例：

```json
{"status":"ok"}
```

### 2.4 关于 Python 窗口

运行项目时出现的 Python 或命令行窗口一般不是错误，而是服务进程。

常见进程：

- 后端 Uvicorn，端口 `8000`。
- 前端 http.server，端口 `5500`。
- 视频识别或调试进程。

不要随意关闭这些窗口。关闭后，浏览器页面可能还在，但后端接口、视频流和识别功能会停止。

## 3. 首页使用说明

### 3.1 首页布局

首页不是宣传页，打开后直接进入业务界面。布局要求如下：

- 左侧为导航栏。
- 顶部显示页面标题、引擎在线状态、本机时间、管理员登录入口。
- 主体区域为实时监控矩阵。
- 左侧导航提供“实时监控矩阵”和“告警事件大屏”。
- 管理员登录后显示更多管理能力。

### 3.2 实时监控矩阵

首页监控矩阵通常显示：

- CAM-01 园区内部围栏。
- CAM-02 码头区域。
- CAM-03 仓库区域。
- SCENE-04 仓库+码头总览。

每个卡片应显示：

- 摄像头名称。
- LIVE 状态。
- 视频画面或等待上传视频。
- 检测框和目标标签。
- 点击后进入具体监控页。

### 3.3 等待上传视频状态

如果当前摄像头没有可用视频源，页面显示“等待上传视频”。该状态已经按统一风格优化，不应出现 `AI Stream Waiting` 这种和其他卡片风格不一致的老样式。

### 3.4 告警事件大屏

点击左侧“告警事件大屏”查看告警。

告警信息包括：

- 告警时间。
- 场景。
- 摄像头。
- 事件类型。
- 告警等级。
- 人数或目标信息。
- 回放入口。

布局要求：

- 最近告警总数不能单独挤占一整行，避免压住 Agent 消息。
- 告警内容应显示中文，不直接显示规则 ID。
- 回放入口应可点击。

## 5. 具体监控页

### 5.1 进入方式

在首页点击某个摄像头卡片，进入具体监控页。

示例：

```text
http://127.0.0.1:5500/module.html?scene=warehouse_dock&camera=cam_warehouse
```

### 5.2 页面布局

具体监控页包括：

- 顶部摄像头和场景信息。
- 当前引擎状态。
- YOLO / VLM 双引擎切换。
- 视频画面。
- 主体模式 / 全目标模式。
- 截图。
- 开始录屏 / 停止录屏。
- 区域编辑。
- 滞留阈值调整。
- 告警或信号信息。

截图和录屏只放在具体监控页，不放在首页。

### 5.3 主体模式和全目标模式

主体模式：

- 主要显示人员。
- 适合演示人员滞留和翻越。

全目标模式：

- 显示更多检测目标。
- 适合调试检测效果。

### 5.4 YOLO / VLM 双引擎切换

具体页顶部支持单摄像头切换：

- YOLO：本地目标检测。
- VLM：视频理解模型。

切换只影响当前摄像头，不影响其他摄像头、不影响其他场景、不改变全局默认方案。

### 5.5 区域编辑

管理员登录后可编辑：

- 围栏线。
- 滞留区域。
- 轨迹通道。

保存后系统会写入规则配置并重载。

### 5.6 滞留阈值调整

管理员可在具体摄像头页修改“几秒判定为滞留”。

建议：

- 演示时可设为 5 秒。
- 正式场景可按需求调整为 10 秒、30 秒或更长。

修改后同时更新：

- 摄像头滞留区配置。
- 对应 dwell 规则配置。

### 5.7 截图

点击“截图”导出当前监控画面。

用途：

- 保存证据。
- 写测试报告。
- 展示识别效果。

### 5.8 录屏

点击“开始录屏”开始录制当前画面，再点击“停止录屏”导出录屏文件。

用途：

- 保存演示过程。
- 复现识别结果。
- 记录异常现象。

## 6. 上传视频测试

### 6.1 上传视频的目的

当没有真实摄像头或需要复现固定场景时，上传视频进行测试。

系统目标行为：

- 上传哪个视频，就识别哪个视频。
- 进入具体页面后继续使用该上传视频。
- 返回首页后不应立即冲刷掉上传视频状态。
- 用户点击“恢复真实摄像头”后才恢复摄像头源。

### 6.2 摄像头 ID

| 摄像头 ID | 说明 |
| --- | --- |
| `cam_fence` | 园区内部围栏 |
| `cam_dock` | 码头区域 |
| `cam_warehouse` | 仓库区域 |

### 6.3 推荐测试流程

1. 启动系统。
2. 登录管理员或进入调试上传入口。
3. 选择摄像头。
4. 上传视频。
5. 进入对应具体监控页。
6. 等待识别框和告警。
7. 从告警进入回放。
8. 点击 MiMo 分析。
9. 用截图或录屏保存结果。

### 6.4 使用手机作为实时摄像头

适用场景：没有 USB 摄像头，或者希望把手机放在现场作为实时摄像头，电脑网页负责显示和检测。

准备条件：

- 手机和电脑连接同一个 Wi-Fi 或同一个局域网。
- 手机安装支持 MJPEG 或 RTSP 的摄像头 App，例如 IP Webcam、RTSP Camera、DroidCam 类工具，或者手机浏览器/推流工具能提供视频流地址。
- 电脑防火墙允许浏览器和后端访问手机 IP 地址。

操作步骤：

1. 在手机端打开摄像头 App，启动视频服务。
2. 记下 App 显示的实时流地址，常见格式为 `http://手机IP:8080/video` 或 `rtsp://手机IP:8554/live`。
3. 在电脑上启动本项目。
4. 打开调试页：

```text
http://127.0.0.1:5500/debug.html
```

5. 使用 Debug 账号登录。默认本地调试账号一般为 `debug`，密码一般为 `123456`，如 `.env` 中修改过则以 `.env` 为准。
6. 在“局域网手机摄像头接入”区域选择摄像头 ID，例如 `cam_fence`。
7. 在“手机摄像头实时流地址”输入框填入手机 App 给出的地址。
8. 点击“绑定手机实时流”。
9. 打开对应监控页，例如：

```text
http://127.0.0.1:5500/module.html?scene=campus_fence&camera=cam_fence
```

10. 如果画面正常，网页会显示手机实时画面，并在画面上叠加检测框和规则状态。

常用地址示例：

| 类型 | 地址示例 |
| --- | --- |
| Android MJPEG | `http://192.168.1.23:8080/video` |
| RTSP 推流 | `rtsp://192.168.1.23:8554/live` |
| HTTPS 视频流 | `https://192.168.1.23:8443/video` |

恢复原始摄像头：

1. 回到 `debug.html`。
2. 选择同一个摄像头 ID。
3. 点击“恢复原始摄像头源”。
4. 刷新监控页，摄像头源会恢复为原来的 `camera://0` 或项目中记录的原始视频源。

排查方法：

- 手机和电脑必须在同一网段，例如都在 `192.168.1.x`。
- 先在电脑浏览器直接打开手机流地址，确认能看到视频。
- 如果浏览器打不开，先检查手机 App 是否仍在运行、手机是否息屏断流、防火墙是否拦截。
- 如果浏览器能打开但系统打不开，尝试换 MJPEG 地址或 RTSP 地址。
- 视频流是长连接，第一次打开可能需要等待几秒。

## 7. 告警说明

### 7.1 告警类型

| 告警 | 场景 | 说明 |
| --- | --- | --- |
| 翻越围栏 | 园区内部围栏 | 人员跨越配置围栏线 |
| 人员滞留 | 园区内部围栏 | 人员在围栏内侧区域停留超过阈值 |
| 码头滞留 | 仓库+码头 | 人员在码头区域停留超过阈值 |
| 仓库滞留 | 仓库+码头 | 人员在仓库区域停留超过阈值 |

### 7.2 告警等级

- 翻越围栏通常为 `high`。
- 滞留事件通常为 `medium`。

### 7.3 告警显示要求

页面应显示中文：

- 翻越围栏。
- 人员滞留。
- 码头滞留。
- 仓库滞留。

不应直接显示：

- `fence_intrusion`
- `fence_dwell`
- `dock_dwell_person`
- `warehouse_dwell`

## 8. 回放使用

### 8.1 打开回放

在告警列表中点击回放入口。

回放页会根据：

- 摄像头 ID。
- 告警时间。
- 场景 ID。
- 规则 ID。

定位对应视频。

### 8.2 回放源类型

回放页会提示视频来源：

- 真实回放录像：最适合分析。
- 上传视频：适合测试。
- 演示兜底视频：仅适合演示，不保证与告警时刻一致。

如果命中演示兜底视频，视频理解结果只能作为参考。

### 8.3 回放检测框

回放页通过 `/replay/detections` 获取当前帧检测框。

如果页面没有显示框，检查：

1. 当前视频是否能读取。
2. 当前播放时间是否有人员。
3. YOLO 模型是否加载成功。
4. 是否选择了正确预览模式。

### 8.4 事件片段裁剪

如果安装了 `ffmpeg`，系统可以生成事件前后短片段。

如果未安装：

- 页面会提示需要 `ffmpeg`。
- 系统仍可直接分析原始回放视频。
- 结果精确度可能低于短片段分析。

### 8.5 片段保存位置

事件短片段保存在项目目录：

```text
data/replay_clips
```

不再放到 C 盘临时目录。

## 9. MiMo 视频理解

### 9.1 配置位置

配置文件：

```text
D:\Project\.env
```

模板：

```text
D:\Project\.env.example
```

关键字段：

```env
MIMO_API_KEY=""
MIMO_BASE_URL="https://api.xiaomimimo.com/v1"
MIMO_MODEL="mimo-v2.5"
```

### 9.2 使用方式

在回放页点击“分析短视频”。

系统会：

1. 优先生成事件短片段。
2. 如果无法裁剪，则使用原始视频。
3. 调用 MiMo。
4. 保存分析结果。
5. 在回放页、告警历史和 Agent 中展示。

### 9.3 分析结果要求

好的视频理解结果应包含：

- 画面中有几个人。
- 人员位于哪里。
- 人员穿着或外观特征。
- 人员正在做什么。
- 是否达到规则中的滞留秒数。
- 是否存在翻越或滞留风险。
- 风险等级和处置建议。

不理想的结果：

- 只说“规则引擎判定滞留”。
- 不描述视频内容。
- 与事件回看中心说法不一致。

遇到不理想结果时，可点击强制重新分析，或调整提示词和规则上下文。

## 13. 常见问题

### 13.1 启动脚本一直卡在健康检查

可能原因：

- 后端没有成功启动。
- 端口 8000 被占用。
- Python 模块路径不正确。

当前已通过 `--app-dir "%PROJECT_ROOT%"` 修复常见模块导入问题。

### 13.2 页面打开但没有视频

处理方法：

1. 检查 `/health`。
2. 确认摄像头是否绑定视频。
3. 上传测试视频。
4. 刷新页面。

### 13.3 MiMo 分析失败

可能原因：

- `.env` 没配置 `MIMO_API_KEY`。
- 网络不可用。
- 视频太大。
- 视频格式不支持。

处理方法：

1. 检查 `.env`。
2. 重启后端。
3. 安装 `ffmpeg`。
4. 使用较短、清晰的 MP4。

### 13.4 回放片段生成失败

可能原因：

- 未安装 `ffmpeg`。
- 找不到回放文件。
- 视频文件损坏或未封口。

当前系统会降级为分析原始视频。

### 13.5 页面仍然是旧样式

可能是浏览器缓存。按：

```text
Ctrl + F5
```

强制刷新。

### 13.6 出现很多 Python 窗口

这些通常是服务窗口。不要随意关闭。当前一键启动已减少自动启动的无关识别窗口。

### 13.7 手机摄像头绑定后没有画面

优先按以下顺序排查：

1. 手机和电脑是否在同一个局域网。
2. 电脑浏览器是否能直接打开手机流地址。
3. 手机 App 是否因为息屏、省电策略或切后台停止推流。
4. 流地址是否写成了网页预览地址，而不是真实视频流地址。常见真实流地址包含 `/video`、`/live` 或 RTSP 路径。
5. 防火墙是否拦截了电脑访问手机端口。
6. 绑定后是否打开了正确的摄像头页面，例如 `camera=cam_fence`。

4. 登录管理员。

6. 进入具体监控页。
7. 调整滞留阈值为 5 秒。
8. 等待识别框和告警。
9. 打开告警回放。
10. 生成回放片段或直接分析原始视频。
11. 查看 MiMo 视频理解。
12. 用 Agent 查询最近告警。
13. 截图或录屏保存演示结果。

手机实时摄像头演示流程：

1. 手机和电脑连接同一 Wi-Fi。
2. 手机启动 IP 摄像头或 RTSP 摄像头 App。
3. 电脑打开 `debug.html`，登录 Debug 账号。
4. 绑定 `http://手机IP:8080/video` 或 `rtsp://手机IP:8554/live`。
5. 打开对应监控页，确认实时画面、检测框和告警状态。
6. 演示结束后点击“恢复原始摄像头源”。
