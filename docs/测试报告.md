## 1. 项目测试对象

本次测试对象为“AI 视频识别信号平台”，系统由以下部分组成：

- 后端服务：FastAPI + Uvicorn，入口为 `backend/app/main.py`。
- 前端页面：静态 HTML 页面，主要位于 `frontend/static`。
- 规则引擎：负责围栏翻越、人员滞留、码头滞留、仓库滞留等事件判定。
- 视觉检测：本地 YOLO 目标检测，用于人员识别和检测框输出。
- 视频理解：MiMo 视频理解模型，用于对回放片段进行语义说明。
- 回放系统：根据告警定位回放、裁剪事件片段、展示检测框和视频理解结果。
- Agent 问答：根据告警和回放数据提供定位建议。
- 管理后台：管理员登录、用户管理、区域配置、阈值配置、日志查看。

## 2. 测试依据与需求覆盖

测试依据来自项目历史开发记录、当前代码和用户提出的所有改动要求。重点覆盖以下需求：

1. 项目能在 `D:\Project` 下稳定启动。
2. 前端首页直接进入监控矩阵，不做营销式首页。
3. 只保留两个核心业务场景：园区内部围栏检测、仓库+码头滞留检测。
4. 首页要展示实时监控矩阵、告警事件大屏、Agent 查询和管理员入口。
5. 具体监控页要支持视频流、检测框、区域编辑、阈值调整、截图、录屏、单摄像头 YOLO/VLM 切换。
6. 上传哪个视频，就识别哪个视频，不再预加载无关老视频。
7. 告警内容要中文化，不能直接显示 `fence_intrusion`、`warehouse_dwell` 这类英文 ID。
8. 回放页面要能定位事件，视频中要尽量带检测框或支持叠框查询。
9. 回放短片段要按事件前后固定时间裁剪；如没有 `ffmpeg`，应提示并降级分析原始视频。
10. MiMo 视频理解要像“视频理解”，描述几个人、在哪里、穿着/行为状态，再结合规则判断是否滞留或翻越。
11. Agent 里的回放链接要变成可点击链接或时间戳按钮，不显示一长串 URL 编码。
12. 视觉叠加层要更商业化，左上角和检测框不能显得老旧。
13. 一键启动不能自动打开多个无关识别窗口。
14. 项目要能打包给组员复现，并提供使用说明。
15. 支持同一局域网下把手机作为实时摄像头：手机开启 MJPEG/RTSP 摄像头服务，电脑网页绑定该实时流并展示检测视频。

### 4.10 局域网手机摄像头接入测试

本轮新增并测试“手机作为实时摄像头”的接入方式。设计思路为：手机和电脑连接同一个 Wi-Fi，手机端运行支持 MJPEG 或 RTSP 的摄像头服务，电脑端通过调试页把摄像头源绑定为网络流地址，再由现有 `/stream/{camera_id}` 视频流链路调用 OpenCV `VideoCapture` 读取实时画面并执行检测。

支持的实时流协议：

- `http://`，常见于 Android IP Webcam 的 MJPEG 地址，如 `http://192.168.1.23:8080/video`。
- `https://`，用于带 TLS 的 HTTP 视频服务。
- `rtsp://`，常见于 RTSP Camera、IP 摄像头或推流工具。
- `rtmp://`，用于 RTMP 推流。
- `udp://`、`tcp://`，用于特定网络视频流场景。

黑盒测试记录：

| 编号 | 测试项 | 操作 | 预期结果 | 结果 |
| --- | --- | --- | --- | --- |
| F-58 | 调试页入口 | 访问 `http://127.0.0.1:5500/debug.html` | 页面包含局域网手机摄像头接入控件 | 通过 |
| F-59 | Debug 登录 | `POST /debug/login` | 返回 Bearer Token | 通过 |
| F-60 | Token 校验 | `GET /debug/ping` 携带 Token | 返回 `ok=true` | 通过 |

## 5. 性能测试

### 5.1 响应速度测试

历史实测记录如下：

| 接口 | 用途 | 状态 | 响应时间 |
| --- | --- | --- | --- |
| `/health` | 健康检查 | 200 | 约 83 ms |
| `/dashboard/overview` | 首页概览 | 200 | 约 39 ms |
| `/signals/scenes` | 场景信号 | 200 | 约 30 ms |
| `/index.html` | 首页静态文件 | 200 | 约 222 ms |

另一轮干净启动实测：

| 接口 | 响应时间 |
| --- | --- |
| `/health` | 约 141 ms |
| `/dashboard/overview` | 约 32 ms |
| `/signals/scenes` | 约 49 ms |
| `/index.html` | 约 210 ms |

结论：

- 常规 JSON 接口响应速度满足本地演示和小规模部署要求。
- 首页静态文件约 130 KB，本地加载约 200 ms，属于正常范围。
- `/stream/{camera_id}` 是 MJPEG 长连接，不适合以普通 HTTP 响应时间衡量，应以连续播放稳定性、推理 FPS、CPU/GPU 占用衡量。

2026-05-14 对新增局域网摄像头能力做了一轮接口黑盒性能测试，共 16 个用例全部通过。HTTP 请求平均响应时间约 `31.15 ms`，最大响应时间约 `104 ms`。其中 `/health` 约 `56 ms`，`/runtime/status` 约 `23 ms`，`/config/rules` 约 `16 ms`，前端首页约 `104 ms`，合法 LAN 流绑定约 `52 ms`，恢复原始源约 `51 ms`。

本轮白盒测试命令：

```powershell
.\.venv\Scripts\python.exe -m py_compile backend\app\api\routes.py backend\app\services\stream_service.py
.\.venv\Scripts\python.exe -m unittest discover -s backend\tests -p "test_*.py" -v
```

结果：核心后端文件编译通过，`unittest` 共运行 `42` 个测试用例，`42/42` 通过。虚拟环境未安装 `pytest`，因此本轮未使用 `pytest`，采用 Python 标准库 `unittest` 完成白盒测试。

| 风险 | 说明 | 处理建议 |
| --- | --- | --- |
| 多视频流并发 | 多个页面同时打开会增加推理压力 | 演示时控制浏览器数量 |
| 热重载卡住 | `--reload` 遇到长连接可能等待关闭 | 一键启动不用 `--reload` |
| MiMo 外部调用慢 | 视频理解依赖网络和模型服务 | 保留缓存，设置超时 |
| ffmpeg 缺失 | 无法精准裁剪短片段 | 正式部署安装 ffmpeg |
| CDN 资源 | 字体、图标、图表依赖外网 | 交付时可本地化资源 |

## 7. 全部关键改错记录

| 问题 | 原因 | 修改结果 |
| --- | --- | --- |
| 启动脚本一直等待 `/health` | 后端模块导入失败 | 加 `--app-dir "%PROJECT_ROOT%"` |
| 后端偶发卡住 | `--reload` 与视频流长连接冲突 | 一键启动去掉 `--reload` |
| Python 窗口过多 | 自动启动多路识别管线 | 一键启动不再自动开多路 worker |
| 告警显示英文串 | 规则 ID 直接展示 | 增加中文标签和中文消息 |
| Agent 链接不可读 | URL 编码直接展示 | 改为可点击时间戳/按钮 |
| 回放视频不准 | 命中 demo 兜底或坏 MP4 | 增加回放源质量提示 |
| `moov atom not found` | MP4 未封口或不可读 | 跳过空文件和不可读文件 |
| 无法裁短片段 | 缺少 ffmpeg | 降级分析原始视频 |
| 视频片段在 C 盘临时目录 | 默认临时目录不便交付 | 改到项目目录 `data/replay_clips` |
| MiMo 只复述规则 | 提示词偏规则解释 | 改为视频内容描述 + 规则判定 |
| 首页布局逼仄 | 告警和 Agent 区域排版不合理 | 调整卡片和消息布局 |
| 视频叠加层老旧 | 左上角和检测框样式粗糙 | 改商业化 HUD 样式 |
| 详情页缺截图录屏 | 基础监控功能缺失 | 在 `module.html` 加截图和录屏 |
| 详情页缺滞留阈值按钮 | 阈值只能改配置文件 | 加页面配置入口和后端接口 |
| 上传视频返回首页后状态丢失 | 页面重新加载覆盖视频源状态 | 调整为保留上传流，主动恢复真实摄像头 |
| 手机网络流被当成本地路径 | `_resolve_source` 统一按文件路径处理字符串 | 对 `http/https/rtsp/rtmp/udp/tcp` 协议直接保留 URL |
| 手机实时流缺少页面入口 | 只能上传或绑定本地视频 | 在 `debug.html` 增加局域网手机摄像头接入面板 |
| 网络流绑定缺少校验 | 任意字符串可能进入配置 | 新增协议白名单和 host 校验，非法协议返回 400 |
| 网络流绑定缺少恢复 | 测试后容易污染摄像头配置 | 新增 `/debug/restore-stream` 恢复原始源 |
| 一键启动与文档不一致 | 脚本仍带 `--reload` | 已从 `start_all_dev.bat` 和 `start_backend_dev.bat` 去掉热重载，优先保证实时视频流稳定 |
