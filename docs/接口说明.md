# AI 视频识别信号平台接口说明

编写日期：2026-05-14（最后更新：2026-06-02）  
版本：v0.3.0  
项目目录：`D:\Project`  
后端基础地址：`http://127.0.0.1:8000`  
前端基础地址：`http://127.0.0.1:5500`  
说明：本文档覆盖系统内部接口、外部接口、配置文件、数据目录和接口调用规则。共计 **75 个** RESTful 端点。

## 1. 接口分类

系统接口分为三类：

1. 系统内部接口：前端页面、规则引擎、回放页、Agent 面板之间调用。
2. 外部接口：MiMo 视频理解、大模型 Agent、未来视频理解 API、CDN 和 ffmpeg。
3. 调试接口：本地开发、上传视频、模拟告警和验收使用。

## 2. 认证方式

### 2.1 管理员认证

管理员登录接口返回 Token。访问受保护接口时添加请求头：

```http
Authorization: Bearer <token>
```

需要管理员权限的功能：

- 新增/删除管理员。
- 用户管理。
- 区域编辑保存。
- 滞留阈值修改。
- 视觉后端配置。
- 查看系统日志和操作日志。

### 2.2 Debug Token

调试上传和模拟接口使用 Debug Token。先调用：

```http
POST /debug/login
```

再携带：

```http
Authorization: Bearer <debug-token>
```

Debug 接口只建议本机开发和演示使用，不建议公开部署。局域网手机摄像头绑定、上传测试视频、模拟告警都属于 Debug 能力。

### 5.1 更新滞留阈值

请求：

```http
POST /api/config/camera/cam_warehouse/dwell-threshold
Authorization: Bearer <token>
Content-Type: application/json
```

Body：

```json
{
  "threshold_seconds": 5,
  "zone_id": "warehouse_zone"
}
```

说明：

- `threshold_seconds` 范围为 1 到 3600 秒。
- `zone_id` 可为空；为空时更新该摄像头所有滞留区。
- 接口会同步更新 `dwell_zones` 和对应 dwell 规则。

### 5.2 更新滞留区 polygon

```json
{
  "region_type": "dwell_zones",
  "points": [[0.1, 0.1], [0.9, 0.1], [0.9, 0.9], [0.1, 0.9]],
  "drawing_mode": "default"
}
```

说明：

- 点位使用归一化坐标，范围 0 到 1。
- 前端区域编辑保存时调用该接口。

### 5.3 更新围栏线

```json
{
  "region_type": "rois",
  "points": [[0.3, 0.4], [0.7, 0.4]],
  "drawing_mode": "line",
  "path_width": 0.08
}
```

### 5.4 更新轨迹通道

```json
{
  "region_type": "rois",
  "points": [[0.2, 0.4], [0.4, 0.5], [0.7, 0.6]],
  "drawing_mode": "trajectory",
  "path_width": 0.08
}
```

说明：

- `trajectory` 模式会生成通道 polygon。
- 适合需要判断目标沿路径进入的场景。

### 9.1 局域网手机摄像头实时流绑定

用途：让手机和电脑在同一局域网下连接，手机作为实时摄像头，电脑网页使用该视频流进行实时检测。

典型流程：

1. 手机连接与电脑相同的 Wi-Fi。
2. 手机打开 IP 摄像头、RTSP Camera 或类似 App，启动 MJPEG/RTSP 服务。
3. 在电脑浏览器访问 `http://127.0.0.1:5500/debug.html`。
4. 登录 Debug 账号获取 Token。
5. 选择摄像头 ID，输入手机流地址并绑定。
6. 打开对应 `module.html` 监控页查看实时检测视频。

请求示例：

```http
POST /debug/bind-stream?camera_id=cam_fence&stream_url=http%3A%2F%2F192.168.1.23%3A8080%2Fvideo
Authorization: Bearer <debug-token>
```

成功返回示例：

```json
{
  "ok": true,
  "camera_id": "cam_fence",
  "stream_value": "http://192.168.1.23:8080/video",
  "message": "局域网实时摄像头地址已绑定，打开对应监控页即可查看实时检测视频。"
}
```

支持协议：

| 协议 | 示例 | 说明 |
| --- | --- | --- |
| `http` | `http://192.168.1.23:8080/video` | 常见 MJPEG 手机摄像头地址 |
| `https` | `https://192.168.1.23:8443/video` | 带 TLS 的 HTTP 流 |
| `rtsp` | `rtsp://192.168.1.23:8554/live` | 常见 RTSP 推流或 IP 摄像头 |
| `rtmp` | `rtmp://192.168.1.23/live/stream` | RTMP 推流 |
| `udp` / `tcp` | `udp://...`、`tcp://...` | 特定网络视频流 |

校验规则：

- `stream_url` 不能为空。
- 协议必须在白名单中：`http`、`https`、`rtsp`、`rtmp`、`udp`、`tcp`。
- `http`、`https`、`rtsp`、`rtmp` 地址必须包含 host。
- 非法协议如 `file://` 会返回 400，避免把本地敏感路径写入摄像头配置。
- 未携带 Debug Token 会返回 401。

恢复原始源：

```http
POST /debug/restore-stream?camera_id=cam_fence
Authorization: Bearer <debug-token>
```

成功后 `config/rules.yaml` 中对应摄像头的 `stream` 会恢复到 `original_stream`，没有记录时默认恢复到 `camera://0`。

| 方法 | 路径 | 说明 | 权限 |

### 10.1 `/replay/info`

查询参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `camera_id` | string | 是 | 摄像头 ID |
| `timestamp` | string | 是 | 告警时间 |
| `scene_id` | string | 否 | 场景 ID |
| `rule_id` | string | 否 | 规则 ID |

返回内容包括：

- 是否找到视频。
- 视频路径。
- 视频时长。
- 视频来源：真实回放、上传视频或演示兜底。
- `clip_generation_supported`：是否支持裁剪片段。
- 已保存的 `video_analysis`。

### 10.2 `/replay/detections`

用途：回放页播放时，根据当前播放秒数返回检测框，用于叠加展示。

参数：

- `camera_id`
- `timestamp`
- `scene_id`
- `rule_id`
- `offset`
- `preview=person|all`

### 10.3 `/replay/analyze`

用途：调用 MiMo 视频理解。

参数：

- `before`：事件前裁剪秒数。
- `after`：事件后裁剪秒数。
- `force`：是否强制重新分析。

返回字段：

- `analysis_target_kind=clip`：使用裁剪片段分析。
- `analysis_target_kind=source_video`：降级为原始视频分析。
- `clip_generation_available`：是否成功生成片段。
- `data.summary`：视频理解摘要。
- `data.risk_assessment`：风险判断。

## 15. 外部接口与依赖

### 15.1 MiMo 视频理解

配置文件：`.env`

```env
MIMO_API_KEY=""
MIMO_BASE_URL="https://api.xiaomimimo.com/v1"
MIMO_MODEL="mimo-v2.5"
MIMO_TIMEOUT_SECONDS="45"
MIMO_VIDEO_FPS="2"
MIMO_VIDEO_MEDIA_RESOLUTION="default"
MIMO_VIDEO_USE_BASE64="1"
MIMO_MAX_COMPLETION_TOKENS="1024"
```

用途：

- 分析回放短片段。
- 描述视频中人员数量、位置、行为。
- 结合规则阈值判断是否滞留或翻越。

注意：

- 文档不能写入真实 API Key。
- 组员使用时应自行填写 `.env`。

### 15.2 Agent 大模型

配置文件：`.env`

```env
API_KEY=""

AGENT_ENABLE_LLM="1"
```

用途：

- 告警摘要。
- 处置建议。
- 自然语言查询。

## 17. 常见状态码

| 状态码 | 含义 | 常见原因 |
| --- | --- | --- |
| 200 | 成功 | 请求正常 |
| 400 | 请求错误 | 参数错误、MiMo 未配置、区域点位不合法 |
| 401 | 未认证 | Token 无效或过期 |
| 403 | 无权限 | 未登录管理员访问受保护接口 |
| 404 | 不存在 | 摄像头、回放、文件、任务不存在 |
| 500 | 内部错误 | 模型、文件、外部 API 异常 |

## 18. 接口调用注意事项

1. 前端默认 API 地址写在页面中：`API_BASE = "http://127.0.0.1:8000"`。
2. 换端口或部署到其他机器时，需要同步修改前端 API 地址。
3. 受保护接口必须带管理员 Token。
4. 视频流是长连接，不适合频繁短请求测试。
5. MiMo 分析会缓存，重新分析需要 `force=true`。
6. `.env` 不应公开传播。
