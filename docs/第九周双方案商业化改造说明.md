# 第九周双方案商业化改造说明

## 1. 改造目标
根据第九周任务安排，项目从单一 YOLO 目标检测链路，升级为 **双方案并存、统一前端复用、统一告警接口复用** 的商业化形态。

目标拆解如下：

1. 继续完善方案一：YOLO 目标检测
2. 增加方案二：视频理解模型后端
3. 前端页面、事件清单、信号输出、Agent 查询接口尽量保持不变
4. 在五一后答辩阶段支持“两套方案一起演示”

## 2. 商业化改造原则

### 2.1 前端不分叉

继续复用现有：

- `/stream/{camera_id}`
- `/alerts`
- `/signals/scenes/{scene_id}`
- `/runtime/status`

这样前端无需为两套方案各写一套页面。

### 2.2 后端抽象化

把视觉后端从“写死 YOLO”改成“可切换视觉引擎”：

- `yolo`：方案一，目标检测 + 跟踪 + 规则引擎
- `video_understanding`：方案二，视频理解模型输出语义事件

### 2.3 运维可观测

新增统一的视觉后端状态与切换能力：

- `GET /vision/backend/status`
- `POST /vision/backend/activate`

便于答辩演示时切换方案，也便于 Agent 查询当前方案。

## 3. 当前已经完成的改造

### 3.1 视觉后端管理器

已新增：

- `backend/app/services/vision_backend_service.py`
- `config/vision_backend.yaml`

功能：

1. 支持读取当前激活方案
2. 支持运行时查看方案状态
3. 支持切换 `yolo / video_understanding`

### 3.2 方案一：YOLO 继续保留

方案一仍然是当前默认激活方案：

- 负责输出目标框
- 负责和跟踪器、规则引擎对接
- 继续支撑当前围栏 / 仓库 / 码头逻辑

### 3.3 方案二：视频理解模型适配层

已新增视频理解后端适配层，支持两种模式：

1. `mock_local`
   - 用于本地联调
   - 在真实视频理解 API 尚未接入前，用于先打通前后端和运行链路

2. `api`
   - 对接外部视频理解模型服务
   - 输入：视频帧 + camera_id + rule_hints
   - 输出：统一语义事件 `VisionRuleEvent`

### 3.4 Agent 能力已接入方案状态

`runtime` 工具和 Agent 现在可以读到：

- 当前激活方案
- 当前后端标签
- 当前管线类型

便于后续在答辩中展示“智能体也知道当前正在跑哪一套方案”。

## 4. 统一接口契约

### 4.1 方案一接口语义

方案一的链路为：

`Frame -> Detections -> Tracking -> Rules -> Alerts -> Signals`

### 4.2 方案二接口语义

方案二的链路为：

`Frame -> Video Understanding Model -> VisionRuleEvent -> RulesEngine.apply_rule_events -> Alerts -> Signals`

### 4.3 统一事件结构

已新增统一语义事件模型：

- `VisionRuleEvent`

关键字段：

- `rule_id`
- `active`
- `count`
- `message`
- `confidence`
- `track_id / track_ids`
- `bbox`

这样视频理解模型后端即使不走 YOLO，也能把结果映射到现有业务规则。

## 5. 当前配置方式

### 5.1 配置文件

- `config/vision_backend.yaml`

### 5.2 环境变量

`.env` / `.env.example` 已支持：

```env
VISION_BACKEND_MODE="yolo"
VIDEO_UNDERSTANDING_PROVIDER_MODE="mock_local"
VIDEO_UNDERSTANDING_API_URL=""
VIDEO_UNDERSTANDING_API_KEY=""
VIDEO_UNDERSTANDING_MODEL=""
VIDEO_UNDERSTANDING_TIMEOUT_SECONDS="12"
VIDEO_UNDERSTANDING_SAMPLE_STRIDE="12"
```

## 7. 下一步建议

按商业方案继续推进时，建议顺序如下：

1. 保持 `yolo` 为稳定默认方案
2. 用 `video_understanding` 的 `mock_local` 模式先跑通流程
3. 再接真实视频理解模型 API
4. 最后在答辩前准备双方案切换演示

## 8. 结论

本次修改后，项目已经不再是“单一 YOLO Demo”，而是朝着 **双后端、统一前端、统一事件总线、统一答辩演示入口** 的商业化工程结构演进。

换句话说，第九周的核心任务已经完成了第一阶段基础设施改造：

- 方案一保留并继续可用
- 方案二接口层已具备接入位置
- 前端无需推翻重写
- Agent 已可感知当前方案状态
